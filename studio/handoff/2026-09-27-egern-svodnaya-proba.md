## Проверено (подробно — CHANGELOG ветки stash-client: ST21, ST22, S-draft-12)

- Stash проверяет узлы В ФОНЕ запросом HEAD: пульс при interval 60 — медиана 1,9 мин,
  без перерывов 1 ч 45 мин; поставщик (interval 300) скачивается в фоне раз в ~4,1 мин.
  Контроллер в фоне почти всегда EOF — скрипт в фоне ничего не видит и не пишет.
- `use`+`filter` — порядок поставщика, не фильтра; слоты работают; закрепления
  переживают фоновые обновления поставщика. Профиль обновляется только на переднем
  плане (экран «Ресурсы»).
- DIRECT у Stash проверяется по `http://www.apple.com/` (stash.wiki proxy-types) —
  отсюда ложные «тайм-ауты» RH-RU (ST21: 33 мин на обходе).
- Тесты: 656/656 на PR #20 (тестировщик, чистый клон).
- Loon 3.5.1: нового для автоматики нет; `tolerance` только у `url-test`, а в
  `routehub.conf` все группы `fallback` — применить не к чему (снято 27.09).

| Вопрос | Egern по документации | Как проверить |
|---|---|---|
| smart-группа | есть (EWMA задержки/джиттера/надёжности, гистерезис), настраиваются `priorities` (PG) | глазами + журнал |

| свой адрес проверки DIRECT | `direct_latency_test_url` (EX), `latency_test_url` группы перекрывает (PG); типа `direct` нет (PX) | журнал |
| фоновое обновление профиля/подписок/наборов | `auto_update`, `update_interval` (PG, RU, EX); фон — не описан | журнал запросов к Worker'у |
| DNS серверов узлов, политика по доменам | `proxy_nameservers`, `forward` по домену/ssid/cellular (DNS) | глазами (обход не трогать) |
| cron / network-скрипт | `schedule`, `network`, `ctx.device` (SC, JS); фон — не описан | cron → `ctx.http` на Worker |
| управление группами из скрипта | нет API (JS, US); ранее «из скрипта нельзя управлять ничем» | только чтение (правило 2) |
