# Студия RouteHub

Как устроена работа над задачей после переезда из Cowork в облачные сессии
Claude Code с подключённым репозиторием `spxload/routehub`. Репозиторий —
единственное место правды: решения, брифы и бэклог живут здесь, а не в
переписке чата.

Образец процесса и ролей — студия `spxload/Teach` (`studio/`), адаптирована
под специфику RouteHub: Worker на Cloudflare, конфиг Loon, стенды под клиентов.

## Порядок работы

| Этап | Что делается | Кто | Выход |
|---|---|---|---|
| 0. Приём | Разобрать запрос, определить сложность (простая / средняя / сложная) и роль | Основная сессия | — |
| 1. Бриф | Короткий бриф в `studio/tasks/T-<имя>.md`: факты (сверены по коду), критерии приёмки, кто исполнитель | Основная сессия | `studio/tasks/T-*.md` |
| 2. Исполнение | Один запуск нужной роли-исполнителя по пути к брифу | executor-simple / -medium / -complex | правки в репозитории |
| 3. Ревью | Диф до коммита: корректность, безопасность, правила 1–5, стиль | reviewer | вердикт: заливать / с поправками / не заливать |
| 4. Тестировщик | Независимая проверка после исполнения, тесты на чистом клоне | tester | вердикт: принято / вернуть на доработку |
| 5. Коммит | Заливка (нативный `git push` этой сессии; для боевого кода — только после согласия Дианы, если задача его касается) | Основная сессия | коммит в репозитории |
| 6. Запись | Обновить `CHANGELOG.md` и снять/добавить пункт `studio/tasks/BACKLOG.md` | Основная сессия | запись в CHANGELOG и бэклоге |

Задача не считается закрытой без вердикта тестировщика (решение Дианы,
22.09.2026). Две задачи, правящие один файл, параллельно не запускаются.

## Роли

| Роль | Сложность | Модель | Задач за раз |
|---|---|---|---|
| executor-simple | простая | opus | пачкой, документы/справки/мелкие правки |
| executor-medium | средняя | opus | 1 агент на 1–3 связанные задачи |
| executor-complex | сложная | opus | 1 агент = 1 задача |
| reviewer | — (ревью) | opus | диф одной задачи |
| tester | — (проверка) | opus | задача одного исполнителя |
| researcher | — (исследование) | opus | один вопрос брифа |

Решение Дианы 24.09: все роли на opus — качество важнее; экономия лимитов
достигается составом задач, а не моделью: мелочи без агентов, агенту — путь
к брифу, ответ агента ≤15 строк, не больше 3 агентов одновременно.

Файлы ролей — `.claude/agents/*.md`. Формат — frontmatter `name` /
`description` / `tools` / `model` по документации Claude Code
(code.claude.com/docs/en/sub-agents): `model` принимает алиас семейства
или `inherit`; в проекте всем ролям задано `opus`; `tools` — список через запятую,
без поля агент наследует все инструменты. Ролям без права записи (`reviewer`,
`tester`, `researcher`) `tools` ограничен чтением, поиском и (для проверки)
запуском команд — без `Write`/`Edit`.

## Экономия лимитов

1. Агент запускается только для объёмной независимой работы. Мелкие правки,
   ответы на вопрос, чтение одного файла — в основной сессии, без агента.
2. Проверки, которые может сделать скрипт или тест, делает скрипт или тест:
   прогон `node --test tests/*.test.js`, а не пересказ агента о том, что код
   «должен работать».
3. Агенту передаётся путь к брифу (`studio/tasks/T-*.md`), а не пересказ
   задачи в промпте.
4. Ответ агента — не длиннее 15 строк; вердикт или итог первой строкой,
   подробности — в самом брифе или отчёте файлом, если нужны.
5. Не больше 3 агентов одновременно.
6. Большие файлы (Worker > 15 КБ, плотные списки правил) в контекст целиком
   не тянуть — точечное чтение, grep, генератор вместо копии.
7. Карта репозитория — `MAP.md` в корне, вместо обхода каталогов агентом.

## Когда спрашивать Диану

Только:
- согласие на боевую правку — `routehub.conf`, боевой Worker, скрипты
  устройства (правило 5);
- необратимое действие;
- действие на телефоне (Loon/Stash), которое не сделать из сессии;
- противоречие в задаче, которое нельзя решить по коду или документам
  проекта.

Вопросы — списком, до начала работы, не по одному после старта.
