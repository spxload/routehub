# RouteHub

Маршрутизация трафика iOS-клиентов (Loon — боевой, Stash — стенд) через
Cloudflare Worker + D1: держит ИИ-сервисы на стабильных узлах, обходит
блокировки РКН, экономит платный трафик обходных узлов. Пользователь —
Диана, работает только с iPhone.

## Что читать

Сначала `MAP.md` — карта и таблица «задача → файлы»; дальше только файлы
под задачу, целиком без нужды не тянуть.

## Жёсткие правила

1. Обходные узлы не тестировать и не гонять через них пробы — платный трафик.
2. Пробы и диагностика НИКОГДА не пишут в боевую маршрутизацию (никаких
   `setSelectPolicy`, `setRunningModel`, правок конфига из скрипта).
3. Токен с правами записи (GitHub и подобные) на телефон не класть: ссылка
   конфига публична по своей природе.
4. MITM не включать на банки, госуслуги и платёжные домены — только точечный
   hostname под конкретную задачу, с исключениями.
5. Не менять боевой конфиг, Worker и скрипты устройства без согласия Дианы.
   Записи в D1 и отвязка ключей — только она.

## Обязательные процедуры

Правка боевого кода или конфига — только после ревью (агент `reviewer`) и
проверки тестировщиком (агент `tester`). Тесты `node --test tests/*.test.js`
на каждом изменении; мутационная проверка для новых тестов. Два агента
параллельно один файл не правят. Парные правки Loon↔Stash: `routehub.conf`
↔ `src/clients/stash-rules.js` (ветка `stash-client`), сторож —
`tests/clients-stash-sets.test.js`.

## Ловушки проекта

- У Stash `$httpClient` timeout в СЕКУНДАХ, у Loon — в МИЛЛИСЕКУНДАХ.
- `setTimeout` в фоне Stash растягивается в 3–4 раза; сторож обязан
  срабатывать позже худшего честного пути (дефект ST14).
- Ровно один `$done` на любой ветви скрипта.
- Отсутствие значения метрики никогда не читается как наилучшее.
- Первый замер скорости занижен; одиночное измерение — не вывод.
- Признак обходного узла — слово «Обход» в любом месте имени (`BYPASS_WORD`).
- `routehub.conf` в ветках `main` и `stash-client` должен совпадать.

## Работа с агентами (решение Дианы 22.09)

Простые задачи — пачкой одному агенту; средние — 1–3 на агента, лучше
связанные одним файлом; сложные — одна на агента; не больше 3 агентов
одновременно; после исполнителей обязателен `tester`. Роли — `.claude/agents/`
(`executor-simple`, `executor-medium`, `executor-complex`, `reviewer`,
`tester`, `researcher`, `ideator`). Процесс и бэклог — `studio/README.md`,
`studio/tasks/BACKLOG.md`. Параметр `model` агенту не передавать:
перекрывает `model: opus` роли.

## Как работать с Opus 5.5

- Нет критерия «готово» (что проверяем) — задачу не начинать.
- Объяснять причину, а не только запрет.
- Отчёт: сделано / проверено / осталось — коротко.
- Ставить задачу через «зачем», а не «как».
- Отвеченное и решённое — решено; без запроса к нему не возвращаться.

## Git и согласие (проверено 24.09)

`git push` в облаке — только в ветку сессии (code.claude.com/docs/en/
cloud-environments#github-proxy); в `main` не пушить. Схема: ветка → PR →
Merge Дианы; Merge в `main` = согласие по правилу 5 (автодеплой). Без
репозитория в источниках сессия не пушит (наблюдение 24.09).

Хук `.claude/hooks/guard-prod.js` спрашивает перед правкой боевого контура;
хуки действуют лишь в сессии с одним репозиторием (cloud-environments «What
carries over»). Правку через Bash он не видит: предохранитель, не замок.

## Контекст (решения Дианы 24.09)

`/compact` не использовать; автосжатие — страховка, не выключать. Первый
запрос сессии — скилл `context-audit`. Монитор `context-watch` (лишь при
одном репозитории) на каждом запросе пишет остаток до точки сжатия. Перед
задачей оценить её объём (мелкая ~20–50 тыс. токенов, средняя ~50–150,
крупная ~150–300+) и сравнить с остатком: влезает — делать до конца, доводя
сессию к точке сжатия; нет — сказать Диане до начала «не поместится —
сделаю в новой сессии» или «сделаю, затем передам дела»; передача посреди
задачи — лишь если она очень большая и прервать нельзя. Ступени: 80 % — новую
большую не начинать, после текущей — `handoff`; 90 % — доделать лишь малое,
иначе передать дела в безопасной точке; 95 % — сейчас.
Диане: «Контекст подходит к концу — запускаю передачу дел (handoff)», после
файла — «Откройте новую сессию Code с репозиторием routehub и напишите:
Продолжи по studio/handoff/<файл>».

## Идеи и проверка невозможного

Перед выводом «невозможно / заблокировано / не работает / не поддерживается» —
скилл `prove-blocked`: вывод только со ступени 4–5 и с контрольным опытом.
При тупике, двух неудачах подряд, на старте сложной задачи, на словах
«оптимизировать / ускорить / улучшить» — роль `ideator`; простые идеи всегда
вместе с нестандартными. В конце закрытой задачи — скилл `ideas`: 1–3 строки
или ничего.

## Стиль ответов Диане

Академичный русский, без воды и вводных фраз; только проверенные факты, нет
данных — «не могу подтвердить»; источники не выдумывать; ошибки признавать
прямо.

## Ветки

`main` — боевое (Loon), автодеплой Cloudflare: любой коммит в `main` уходит
в бой. `stash-client` — стенд Stash, в `main` не сливать до решения.
`egern` — архив отдельного проекта.
