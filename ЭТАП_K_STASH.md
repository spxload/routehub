# ЭТАП K — STASH: проба возможностей ST1

> Назначение файла: как подключить пробу, что она измеряет, как забрать отчёт
> и по каким признакам судить о пригодности Stash для RouteHub.
> Источник сведений о Stash — официальная документация `https://stash.wiki/en`
> (разделы Manage Scripts, Syntax & Interface, Scheduled Tasks, Override,
> Configuration Example, Proxy Groups). Даты страниц — 25.06.2026.

---

## 1. Зачем

По итогам сравнения трёх клиентов Loon остаётся единственным, где управление
из скрипта подтверждено измерением. Stash в тот круг не входил. По документации
у него есть два механизма, критичных для RouteHub, и один, которого нет ни у
Loon, ни у Egern. Проба ST1 проверяет их на устройстве, ничего не меняя.

---

## 2. Что известно ДО пробы (только документация, не измерение)

| Свойство | Значение | Раздел документации |
|---|---|---|
| Протокол VLESS | поддерживается | Intro |
| Плановые скрипты | секция `cron`, выражения crontab | Scheduled Tasks |
| Скрипт по ссылке | `script-providers` c `url` + `interval` | Manage Scripts |
| Адресация узла в запросе | заголовок `X-Stash-Selected-Proxy`, имя URL-кодировано | Syntax & Interface |
| Хранилище | `$persistentStore.read/write` | Syntax & Interface |
| Уведомления | `$notification.post(title, subtitle, body)` | Syntax & Interface |
| Обязательный финал скрипта | `$done(value)` | Syntax & Interface |
| Таймаут запроса по умолчанию | 5 с, переопределяется полем `timeout` | Syntax & Interface |
| Группы по SSID | `ssid-policy` внутри группы типа `select` | Proxy Groups |
| Цепочка узлов | `dialer-proxy` | Dialer Proxy |
| Движок скриптов | WebKit | Intro |

Чего в документации НЕТ и что проба обязана выяснить: метода переключения
политики из скрипта. Именно этим Egern и проиграл.

---

## 3. Ограничения, снятые заранее

1. **Один активный VPN на iOS.** Пока работает Loon, туннель Stash не поднят,
   а плановые задания без поднятого туннеля не выполняются (Scheduled Tasks).
   Проба требует отдельной сессии с явным переключением клиента. Это те же
   грабли, на которых оборвался прогон Shadowrocket (SR3).
2. **Профиль нужен рабочий.** Без узлов шаг адресации проверить не на чем.
3. **Проба ничего не меняет.** Единственная запись — временный ключ
   `RH_probe_tmp`, он же удаляется в конце шага 5.

## 4. Подключение

### Способ 1 — одной ссылкой (рекомендуется)

Открыть на телефоне:

```
https://link.stash.ws/install-override/raw.githubusercontent.com/spxload/routehub/main/RouteHub-Probe.stoverride
```

Stash предложит установить переопределение. Основной профиль не изменяется:
override — отдельный файл поверх конфига (раздел Override).

### Способ 2 — вручную в профиле

Настройки → Конфигурационный файл → выбранный профиль → правка. Добавить:

```yaml
script-providers:
  routehub-probe-stash:
    url: https://raw.githubusercontent.com/spxload/routehub/main/routehub-probe-stash.js
    interval: 86400

cron:
  script:
    - name: routehub-probe-stash
      cron: '*/5 * * * *'
      timeout: 40
```

Имя в `cron.script[].name` обязано совпадать с ключом в `script-providers`.

### Шаг адресации узла (необязательный, но самый ценный)

В задание добавляется строка с точным именем узла из профиля:

```yaml
      argument: '{"node":"🇩🇪 Германия [VPN] #1"}'
```

Без неё шаг 9 помечается пропущенным, остальные восемь выполняются.

### Порядок запуска

1. Выключить Loon.
2. Включить туннель Stash, убедиться, что интернет идёт через него.
3. Дождаться ближайшей пятиминутки либо перезапустить туннель.
4. Забрать отчёт (раздел 6).

---

## 5. Что измеряет ST1 (девять шагов, один прогон)

| Шаг | Имя в отчёте | Что выясняет |
|---|---|---|
| 1 | `globals` | сплошная опись глобальных имён и прототипа (вывод 54: выборочный перебор негоден) |
| 2 | `api` | наличие ожидаемых интерфейсов: `$httpClient`, `$persistentStore`, `$notification`, `$config`, `$stash`, `$task`, `$utils`, `$network` и др. |
| 3 | `members` | опись членов найденных объектов — ищем методы управления политикой |
| 4 | `argument` | доходит ли `argument` планового задания до скрипта |
| 5 | `store` | запись, чтение, наличие `remove`; ключ удаляется |
| 6 | `perf` | миллион итераций; сравнение: Egern 7 мс, Loon 12, Shadowrocket 40 |
| 7 | `websocket_ctor` | есть ли класс WebSocket и создаётся ли объект |
| 8 | `net_direct`, `net_ip` | сетевые запросы: `connectivitycheck.gstatic.com` и `api.ipify.org` |
| 9 | `net_node` | тот же запрос через `X-Stash-Selected-Proxy` — работает ли поузловая адресация |

Схема прогона по выводу 56: все шаги за один запуск, ошибка шага пишется в
отчёт и перебор продолжается, общий бюджет 25 с, предохранитель отправляет
отчёт даже при зависшей сетевой цепочке.

## 6. Отчёт

Проба шлёт POST на открытый приёмник стенда (токен устройства не требуется,
доступа к подписке не даёт):

```
https://routehub-egern.proton4iker.workers.dev/ingest/rh-drop-2026?src=stash-ST1
```

Забрать — тем же адресом методом GET, из браузера. Если POST не прошёл, отчёт
остаётся в консоли скриптов Stash (`console.log` пишется в отдельный файл).

---

## 7. Как читать результат

**Stash становится кандидатом на миграцию, если одновременно:**

1. в шаге 3 найден метод выбора политики группы (аналог `setSelectPolicy`);
2. шаг 9 вернул статус 204/200 и время, отличное от прямого запроса, — то есть
   адресация узла действительно работает;
3. шаг 5 подтвердил хранилище;
4. шаг 4 подтвердил, что `argument` доходит (в Loon в generic-скрипте его нет).

**Stash отпадает, если** метода управления политикой не нашлось: тогда он
повторяет положение Egern — богатая среда без управляемости, а ради `ssid-policy`
и `dialer-proxy` терять переключение из скрипта смысла нет.

Отдельно фиксируется рабочесть скриптов по ссылке под активным whitelist:
Shadowrocket на этом отсеялся (тело скрипта не загружается).
