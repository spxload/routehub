## 1. ИТОГИ ПОЛЕВЫХ ПРОГОНОВ k4-1 и k4-2 (2026-08-08, Egern 2.20.0, k3)

### 1.1 Работает
- **[k3]** `schedule`-скрипт по cron **без MITM и без перехвата**. Пятипольная
  запись нормализуется в шестипольную (`*/5 * * * *` → `0 */5 * * * *`).
- **[k3]** `ctx.http` с `policy` = **имя группы** и `DIRECT`. Задержки на k3:
  без политики 97 мс, через группу 91 мс, `DIRECT` 99 мс.
- **[k3]** `POST` отчёта на Worker — телеметрия доходит, семь прогонов подряд
  без пропусков, ровно по расписанию.
- **[k3]** `ctx.storage`: строки, JSON, удаление, счётчик между прогонами.
  Записались и прочитались **32 КБ, 256 КБ и 1 МБ** — предел значения выше 1 МБ.
- **[k3]** Параллельность: 5 одновременных запросов через группу — 109 мс.
- **[k3]** `ctx.compress`: 576 → 36 байт gzip, → 26 байт brotli, распаковка без потерь.
- **[k3]** HTTPS, `HEAD`, `redirect: "manual"` (301 не разворачивается),
  заголовки ответа (`r.headers.get('server')`).
- **[k3]** Движок быстрый: 10⁶ итераций за 7 мс. Есть `fetch`, `WebAssembly`,
  `Intl`, `TextEncoder`, `URL`, `btoa`, `setTimeout`. Часовой пояс `Europe/Moscow`.

### 1.2 Не работает
- **[k3]** **Узел по имени в `policy` не адресуется.** Имя узла, несуществующее
  имя политики и `REJECT` дают одинаковый **404 без заголовка `server`** —
  отвечает сам Egern. Причина: узлы приходят из подписки (`external`/`urls`) и
  не объявлены как `proxies`.
- **[k3]** `policyDescriptor` — внутренняя ошибка `400 / Error`.
- **[k3]** `crypto.subtle` отсутствует (`crypto` есть, `subtle` — `undefined`).
  HMAC на устройстве штатно не посчитать.
- **[k3]** `ctx.lookupIP` **ненадёжен**: 8.8.8.8 → `US / AS15169 / GOOGLE`
  верно, но адрес выхода `111.88.96.82` → `PK` с пустыми `asn` и `organization`,
  тогда как Cloudflare по тому же соединению вернул `loc=RU`, `colo=ARN`.
  Подтверждает вывод 4 проекта: **страна берётся из имени узла, не из GeoIP**.
- **[k3]** Отказ соединения приходит **исключением** с текстом
  `HTTP error! status: 400, body: Error` — это обёртка Egern, а не ответ сервера.
- **[k3]** `Object.keys(ctx)` не показал ничего сверх документации:
  `script, env, app, device, request, response, http, storage, notify, lookupIP,
  compress, ssh, cron, widgetFamily, respond, abort`.

### 1.3 Сведения об устройстве, недоступные в Loon
- **[k3]** `ctx.device` отдаёт `ssid`, **`bssid`**, `carrier`, **`radio`** (LTE),
  адрес, шлюз, интерфейс, список DNS. В Loon доступен только `ssid`.

## 2. ГРУППЫ ПОЛИТИК — ПОЛНЫЙ НАБОР **[док]**

Семь типов: `select`, `auto_test`, `smart`, `fallback`, `load_balance`,
`external`, `conditional`. Встроенные политики: `DIRECT`, `REJECT`.

### 2.1 Общие поля пяти основных типов
`name`, `policies` (имена прокси, других групп или встроенных политик),
`urls` (**подписки монтируются прямо в группу**), `filter` (regex по именам),
`flatten` (разворачивать узлы вложенных групп), `update_interval`,
`block_quic` (**на группу**), `icon` (SF Symbols или URL), **`hidden`**
(скрыть группу в интерфейсе), **`prev_hop`** (цепочка прокси),
`latency_test_url`.

**`external` — легаси.** Документация прямо говорит: он эквивалентен `urls` на
обычной группе нужного типа, но не поддерживает `policies` и `flatten`.
Наш профиль сейчас построен на `external` — стоит перевести на обычные группы.

### 2.2 `smart` — есть, и с `priorities`
Ранжирует кандидатов по совокупности задержки, джиттера и надёжности; сглаживает
выбросы EWMA; переключается с гистерезисом и минимальным временем удержания;
сам подстраивает частоту проб. Параметры сглаживания не настраиваются.

`priorities` — объект: **ключ regex по имени кандидата, значение коэффициент**;
`< 1` повышает приоритет, `> 1` понижает, **`0` — всегда выбирать первым** с
откатом на прочие при отказе. Первое совпавшее правило выигрывает, точное имя —
`^имя$`.

Это прямая замена серверному рейтингу RouteHub: Worker может отдавать не порядок
узлов, а коэффициенты.

### 2.3 `conditional` — выбор по сетевому окружению
Правила трёх видов с glob-масками: `ssid`, **`bssid`**, `cellular`
(`NR`, `NRNSA`, `LTE`, `WCDMA`, …), плюс обязательный `default_policy`.
Первое совпадение выигрывает.

Это заменяет всю логику `routehub-netwatch.js` **без единого скрипта**.
Домашняя сеть k3 уже известна из прогона: SSID `fh_862d68_5G`,
BSSID `c4:64:b6:86:2d:6c`.

### 2.4 `load_balance` — два алгоритма
`hash` (по умолчанию) — соединения к одному домену/IP закрепляются за одним
узлом; `round_robin` — ротация, адрес выхода не фиксирован. Оба пропускают
узлы, не прошедшие health-check.

`hash` интересен для ИИ-сервисов: закрепление по назначению — это и есть sticky,
ради которого в Loon написан отдельный скрипт.

### 2.5 `fallback` и `auto_test`
`fallback`: `interval` (по умолчанию 600), `timeout` (5, максимум 60).
`auto_test`: `interval`, `tolerance` (100 мс), `timeout`.
Подтверждено полем: к члену `DIRECT` применяется **групповой**
`latency_test_url` (проверка K2).

## 3. ВИДЖЕТЫ — ДАШБОРД БЕЗ ВНЕШНЕЙ ПАНЕЛИ **[док]**

Виджет описывается в поле `widgets` (`name`, `script_name`, `env`) и рисуется
`generic`-скриптом, который **возвращает JSON-DSL**. Элементы: `widget` (корень),
`stack` (флекс-контейнер), `text`, `image` (SF Symbol, base64 или SVG), `spacer`,
`date` (обновляется системой). Свойства: `url` (переход по нажатию), `padding`,
`gap`, `flex`, `backgroundColor`, `backgroundGradient`, `backgroundImage`,
`borderRadius`/`borderWidth`/`borderColor`, `shadowColor`, `opacity`.
Размеры: `systemSmall/Medium/Large/ExtraLarge`, `accessoryCircular/Rectangular/Inline`.

Следствие: локальный дашборд `http://rh.box` на Egern не нужен — экран Analytics
плюс собственный виджет на домашнем экране закрывают ту же задачу, причём данные
берутся из `ctx.storage`, который переживает перезапуск.

## 4. ЧТО ЭТО МЕНЯЕТ ДЛЯ RouteHub

| Узел системы | Сейчас в Loon | На Egern |
|---|---|---|
| выбор узла | `fallback` + порядок от Worker | `smart` + `priorities` от Worker |
| sticky для ИИ | скрипт + select-группы | `load_balance` с `hash` **[?]** |
| Wi-Fi / сотовая | `routehub-netwatch.js` | `conditional` по `ssid`/`bssid`/`cellular` |
| дашборд | `http://rh.box` + скрипты | виджет из `generic`-скрипта |
| спидтест по узлам | `$httpClient.get({node})` | **невозможен напрямую**; обход — п. 5 |
| страна узла | из имени (GeoIP не верить) | так же; `ctx.lookupIP` подтверждённо врёт |
| телеметрия | `POST /speed` | `ctx.http.post` из `schedule` — работает |
| подпись данных | HMAC на Worker | `crypto.subtle` нет, только чистый JS |

## 5. ОБХОДНОЙ ПУТЬ ДЛЯ СПИДТЕСТА **[?]**

Раз `policy` принимает имя **группы**, а группа умеет `urls` + `filter`, то на
каждый узел можно сгенерировать группу-обёртку:

```
- select:
    name: "RH-Узел-001"
    urls: ["<ссылка на /nodes>"]
    filter: "^<точное имя узла>$"
    hidden: true
```

Тогда `ctx.http.get(url, { policy: "RH-Узел-001" })` измеряет конкретный узел.
Поле `hidden` держит 52 служебные группы вне интерфейса. Проверяется одной
группой, прежде чем генерировать полсотни.

## 6. ПЛАН СЛЕДУЮЩЕЙ ПРОВЕРКИ

**Профиль (Worker e0.4.0), по одной конструкции за импорт — Egern падает на
первом несоответствии типа:**
G1 `smart` с `priorities` (закрывает K5) · G2 `conditional` по домашним SSID и
BSSID · G3 перевод пулов с легаси-`external` на обычные группы с `urls` ·
G4 скрытая группа-обёртка на один узел (п. 5) · G5 `load_balance` с `hash` ·
G6 `generic`-скрипт и `widgets` — виджет-дашборд · G7 `http_request`-скрипт на
`http://cp.cloudflare.com/generate_204` — перехват plain-HTTP без MITM,
результат читает проба `P30`.

**Скрипт (ревизия k4-3) — поиск недокументированного:**
U1 перечисление собственных и прототипных свойств `ctx.http`, `ctx.storage`,
`ctx.compress`, `ctx.ssh`, `ctx.notify` · U2 перечисление `globalThis` ·
U3 проверка догадок об управлении (`setPolicy`, `selectPolicy`, `groups`,
`stats`, `analytics`, `traffic`, `connections`, `proxies`, `config`, `log`,
`fs`) · U4 локальный управляющий интерфейс: `127.0.0.1` на типовых портах ·
U5 глобальный `fetch` против `ctx.http` — идёт ли он мимо туннеля ·
U6 реальная работа `WebAssembly` · U7 таймеры · U8 перечисление `ctx.ssh` ·
U9 `ctx.request`/`ctx.response` в `schedule` (ожидается `undefined`) ·
U10 возврат виджет-DSL из `schedule` · U11 перечисление ключей `ctx.storage`
(`keys`, `list`, `all`) · U12 `policy` = группа с членом `DIRECT`.
