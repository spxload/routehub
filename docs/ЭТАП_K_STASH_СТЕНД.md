### Разово, чтобы стенд ожил

1. **Cloudflare → Workers → Create → импорт `spxload/routehub`, ветка `main`.**
   Имя воркера — `routehub-stash`.
2. **Deploy command:** `npx wrangler deploy --env stash` (без флага
   развернётся боевой конфиг — это важно не перепутать).
3. **Секреты:** `SUBSCRIPTION_URL`, `SUB_HWID`, `ADMIN_KEY`. По ADR-01 их стоит
   сразу завести в **Secrets Store** и привязать к обоим воркерам — тогда
   следующему контуру вписывать нечего.
4. **Заодно у боевого воркера** сменить deploy command на

   уровень лучше выбирать явно.

### Шаги проверки Stash — редакция 16.08, ТОЛЬКО С ТЕЛЕФОНА

Прежняя редакция начиналась с `curl` к контроллеру телефона с ноутбука.
Ноутбука в проверках больше нет: всё, что ниже, делается на самом iPhone.
Порядок переставлен так, чтобы дешёвое и выполнимое шло первым.

**Шаг 1. Экран «Connections» в самом Stash.** Ничего включать не нужно.
Приложение показывает активные соединения и умеет доставать имя хоста
снифферингом: TLS Client Hello (SNI), QUIC/HTTP3 и HTTP-запросы внутри TCP
(Method, Host, URL) — release notes iOS. Рядом есть экраны **HTTP Inspection**
и **DNS Inspection**.
*Что закрывает:* вывод 8 — журнал незагрузившихся доменов — **без MITM и без
API вообще**. Если имена видны, задача, ради которой обсуждался MITM, решается
штатным экраном.

**Шаг 2. zashboard в Safari телефона** на `http://127.0.0.1:9090`, ключ —
`Authorization: Bearer <ключ>`. Контроллер на этом адресе уже отвечал в пробах
ST3–ST5 (замер 12.08, см. ниже), то есть шаг проверяет не доступность
контроллера, а годность самой панели.
*Что закрывает:* если заведётся — своей панели для Stash не пишем.
*Оговорка:* ключ API берётся в приложении, «More Settings». Он же
подставляется автоматически в «Tools → Remote Controller» между устройствами
одного iCloud.

**Шаг 3. `/connections` через панель.** Эндпоинт существует и отдаёт ~19 КБ
(замер 12.08). Открытый вопрос ровно один: видно ли там имя хоста, а не только
IP. Если шаг 1 уже показал имена в приложении, этот шаг становится
необязательным — он нужен, только если журнал хочется собирать автоматически.

**Шаг 4. `ssid-policy`** вместо пары групп `-W` / `-C`.
**Уточнение к прежней записи: отдельного типа группы `ssid` в Stash нет.**
Есть параметр `ssid-policy` у группы типа `select`, с зарезервированными
значениями `default` и `cellular`:

```yaml
- name: ssid-group
  type: select
  proxies: [ss1, ss2, ss3, DIRECT]
  ssid-policy:
    office: ss1
    home: ss2
    cellular: ss3
    default: DIRECT
```

Если ни `default`, ни `cellular` не заданы, переключение не срабатывает вовсе.
*Что даёт:* конфиг схлопывается вдвое, уходит `routehub-netwatch.js` и
дублирование узлов в `/nodes`. Нужен `src/clients/stash.js`, собирающий YAML.

**Шаг 5. `consistent-hashing`** для AI. Это не тип группы, а параметр
`strategy` у группы `load-balance`; документация прямо рекомендует его, чтобы
не менять IP часто и не будить защиту сервиса.
*Что даёт:* per-site sticky штатными средствами, без страновых тиеров.

**Отложено до ноутбука (не делаем):** доступ к контроллеру с другого
устройства по локальной сети. Документация Stash описывает только
«Remote Controller» между устройствами одного iCloud; про привязку API к
`127.0.0.1` или `0.0.0.0` и про порт по умолчанию в вики не сказано ничего.
Параметр «Allow LAN connections» в документации относится к HTTP/SOCKS-прокси
на порту 7890, а не к API.

### Что подтверждено документацией Stash (сверка 16.08)

Проверялась вики `stash.wiki` целиком (42 страницы, обе языковые версии).

| Факт | Статус |
|---|---|

| «Tools → Remote Controller» — управление другим устройством Stash в локальной сети под тем же iCloud | подтверждено |
| Порт API, поля `external-controller` / `secret` в конфиге | **в документации нет**; наш замер 12.08 даёт `127.0.0.1:9090` |
| Встроенная веб-панель (`external-ui`) | **в документации нет** |
| Эндпоинт `/connections` | **в документации нет**; наш замер 12.08 подтверждает |
| Экран «Connections» с именами хостов через сниффинг SNI / QUIC / HTTP | подтверждено |
| Экраны HTTP Inspection, DNS Inspection, Network Quality Test, управление данными скриптов | подтверждено |
| `$persistentStore.read / .write` | подтверждено |
| `$httpClient` — все методы; **выбор узла заголовком `X-Stash-Selected-Proxy`**, не параметром `node` | подтверждено |
| Таймаут запроса по умолчанию 5 с | подтверждено |
| Cron-скрипты (`cron.script`), только JavaScript, **требуют поднятого Network Extension** | подтверждено |
| Типы скриптов: `request`, `response`, `tile` | подтверждено |
| `ssid-policy` у группы `select`, значения `default` и `cellular` | подтверждено |
| `consistent-hashing` — `strategy` группы `load-balance` | подтверждено |
| Типы групп: `url-test`, `fallback`, `load-balance`, `select`, `relay` | подтверждено |
| Override: массивы **вставляются в начало** исходного массива; правка отдельных элементов массива не поддерживается; `#!replace` заменяет целиком | подтверждено |
| Экспорт логов с устройства | **в документации нет**; `console.log` пишется в отдельный файл, способ забрать не описан |

**Поправка к прежней записи об `SCRIPT`-правилах.** Синтаксис
`SCRIPT,<shortcut>,POLICY` существует, но `<shortcut>` — это **выражение на
Python** из секции `script.shortcuts`, возвращающее bool, а не JavaScript.
Доступны `network`, `host`, `dst_ip`, `dst_port`, `src_ip`, `src_port` и
функции `resolve_ip()`, `in_cidr()`, `geoip()`, `ipasn()`, `match_provider()`,
`match_geosite()`. Значит маршрутизировать по нашему композитному баллу через
`SCRIPT` нельзя — это отличие Stash от Loon и Surge. Прежняя формулировка
«могут заменить половину логики групп» относилась к маршрутизации по IP,
ASN и geosite и в этом объёме верна.

## Чего в Stash нет

- **smart-группы.** Замена — `consistent-hashing` плюс наш композитный балл,
  который в отличие от Surge учитывает ещё и скорость.
- **Нативного спидтеста.** Переносим свой скрипт.
- **Включения MITM из API.**
- Ручной запуск скрипта — только плитка (`$script.type = tile`), `$argument`
  в плитке нет.
- Маршрутизации JavaScript-скриптом: `SCRIPT`-правило принимает Python-выражение,
  не JS (см. поправку выше).

## Что известно про контроллер (ЭТАП_K_STASH.md, замер 12.08)

`http://127.0.0.1:9090`, порт ядра 7890. Без ключа — 401 везде.
Живые пути: `GET /`, `/proxies`, `/proxies/{имя}`, **`PUT /proxies/{имя}` → 204**,
`/proxies/{имя}/delay`, `GET /configs`, **`PATCH /configs` → 204**, `/rules`,
`/connections` (~19 КБ), `/providers/proxies`, `ws://…/traffic?token=`.
404: `/version`, `/status`, `/api*`, `/v1*`, `/policies`, `/groups`, `/scripts`,
`/tiles`, `/ui`, `/dns/query`.

## Почему база всё-таки отдельная

Реестр устройств хранит `nonce`. Общая база перепривязала бы боевые ключи k1/k2
(вывод 12). Экономии на общей базе нет: квоты D1 считаются на аккаунт, а не на
базу (5 млн чтений строк в сутки, 100 000 записей, 5 ГБ суммарно). Значит
объединение баз давало бы только риск — отклонено в ADR-01.
