это K1–K10 и ревизии скрипта k4-1…k4-16 (Egern 2.20.0, k3, 08–11.08.2026).

## 3. Состав сводной пробы EGS (отдельный профиль на k3, без узлов с «Обход»)

Все адреса проверки — `<стенд Stash>/lab/pulse?t=<метка>`
(метка `[a-z0-9-]{1,16}`, в журнал пишется только `{lab:"pulse", t, ts}`; `src/clients/stash-lab.js`).
Пульсы — ТОЛЬКО у групп из DIRECT и муляжей TEST-NET (ловушка Cloudflare 400 через узлы).
Муляж = `socks5` на 192.0.2.x (как RH-Т23-Муляж). Скрипт пробы только читает: `ctx.http` с
`policy` = тестовая группа; ни одного вызова, меняющего выбор (правило 2). Режим прогона:
10 мин приложение открыто → 40 мин смахнуто, VPN включён → 20 мин экран заблокирован → две
смены Wi-Fi↔сотовая. Метки ниже — предложение.

## 4. Условия, чтобы проба не дала ложных выводов

- Секунды у `interval`/`timeout` групп и скриптов, миллисекунды у `ctx.http`/`ctx.ssh` (PG, SC, JS).
- Профиль EGS не править в UI (помеха опыта auto_update); cron задавать в профиле.
- Каждая «нет» — только при наличии контроля «да» в том же прогоне (пульс переднего плана).
- 404 и 400 у Egern неинформативны (ЛАЗЕЙКИ §10); сравнивать только с контролем.
- Записывать версию Egern: на странице App Store 2.20.0 (AS), дата в пересказе расходится.
- Нужны от Дианы (правило 5): маршруты `/lab/eg-nodes`, `/lab/eg-profile` (asn/org), медленный пульс.

## 5. Не подтверждено (документация молчит)

- Фон для health-check групп, скачивания подписки, auto_update, schedule/network-скриптов.
- Сохранение порядка узлов подписки внутри группы; адрес проверки у smart; смысл «unreachable».
- Минимальные значения `interval` групп и `auto_update`.
- Путь резолва имён серверов узлов (default vs proxy DNS).
- Любой API чтения/смены выбора групп из скрипта (в JS отсутствует; противоречие с SC открыто).
