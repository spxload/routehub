# Передача дел

ЗАЧЕМ. Сессии не видят переписку друг друга — только репозиторий. `/compact`
сжимает контекст внутри той же сессии и теряет детали без следа; файл
передачи остаётся в репозитории, его читает любая следующая сессия.

## Куда

`studio/handoff/<ГГГГ-ММ-ДД>-<тема>.md`, тема — два-три слова латиницей или
кириллицей через дефис. Файл коммитится в ветку текущей сессии; в ответе
Диане назвать ветку и PR, чтобы следующая сессия знала, откуда читать, если
PR ещё не слит.

## Что писать (по-русски, коротко)

1. **Цель** — одна-две фразы: что должно получиться и критерий «готово».
2. **Сделано** — коммиты (SHA) и PR (номер) со строкой смысла на каждый.
3. **Проверено** — чем именно: тесты (сколько прошло), сверки, пробы;
   одиночное измерение пометить как одиночное.
4. **Осталось** — по пунктам, в порядке выполнения.
5. **Открытые вопросы к Диане** — нумерованным списком, к каждому ответ по
   умолчанию (формат скилла `grill-me`).
6. **Открыть первыми** — 3–6 путей к файлам, с которых начинать.
7. **Скиллы** — какие скиллы следующей сессии вызвать и зачем.

Если аргумент передан — это описание следующей сессии: подстроить файл под
неё, лишнее не переносить.

## Правила

- Не дублировать то, что уже лежит в репозитории (брифы `studio/tasks/`,
  ADR, CHANGELOG, диффы) — давать путь или ссылку.
- Репозиторий публичный: никаких токенов, ключей, значений нонсов, адресов
  устройств и Worker'а, персональных данных. Вместо значения — `<REDACTED>`.
- Решённое записывать как решённое, с датой: следующая сессия к нему не
  возвращается без запроса Дианы.
