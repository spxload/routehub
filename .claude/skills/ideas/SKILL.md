# Идеи на потом

ЗАЧЕМ. Лучшие идеи замечаются по ходу работы и теряются с концом сессии.
Но простыня предложений в каждом ответе съедает лимиты и внимание Дианы —
поэтому фильтр жёсткий, а молчание — нормальный исход.

## Когда

Только после закрытия задачи, последним блоком ответа. Посреди работы, при
открытых вопросах, при провале задачи — не применять (провал → скилл
`prove-blocked` или роль `ideator`).

## Фильтр — идея проходит, если все три «да»

1. Замечена в ЭТОЙ задаче, а не придумана ради блока.
2. Экономит заметное: повторяющийся ручной шаг, чтение большого файла,
   проверку, которую может делать тест/скрипт; или закрывает хрупкое место.
3. Не нарушает правила 1–5 (обходные узлы не трогать, в маршрутизацию не
   писать) и ещё не записана в бэклог (`studio/tasks/BACKLOG.md`).

Ни одна не прошла — блок не выводить совсем, без «идей нет».

## Формат

```
Дальше: <суть> — <что сэкономит> — <первый шаг>.
```

Не больше трёх строк, простые впереди. Без агента, без поиска, без
дополнительных вызовов инструментов: только то, что уже видно. Нужен
глубокий разбор — предложить одной строкой роль `ideator`, не запускать.
