## Что должна сделать Диана

### Разово, чтобы стенд ожил

1. **Cloudflare → Workers → Create → импорт `spxload/routehub`, ветка `main`.**
   Имя воркера — `routehub-stash`.
2. **Deploy command:** `npx wrangler deploy --env stash` (без флага
   развернётся боевой конфиг — это важно не перепутать).
3. **Секреты:** `SUBSCRIPTION_URL`, `SUB_HWID`, `ADMIN_KEY`. По ADR-01 их стоит
   сразу завести в **Secrets Store** и привязать к обоим воркерам — тогда
   следующему контуру вписывать нечего.
4. **Заодно у боевого воркера** сменить deploy command на
   `npx wrangler deploy --env=""`: в конфиге появились окружения, и верхний
   уровень лучше выбирать явно.
5. Проверить: `/admin` стенда открывается, в базе стенда появляется `devices`.

### Шаги проверки Stash (от дешёвого к дорогому)

Первые три ничего не меняют в боевом контуре и делаются за полчаса.

**Шаг 1. Контроллер по сети.** В Stash включить Allow LAN. С ноутбука в той же
сети:

```
curl -H "Authorization: <ключ из $environment['controller-authorization']>" \
     http://<IP телефона>:9090/proxies
```

Ключ уже содержит слово `Bearer` — передавать как есть. Если ответит, появляется
управление с компьютера, как у Surge на `0.0.0.0:6171`, и часть скриптов на
телефоне становится не нужна.

**Шаг 2. zashboard.** Открыть в Safari телефона, затем с компьютера. Если
заведётся — свою панель для Stash не пишем вовсе.

**Шаг 3. `/connections`.** Посмотреть, видно ли имя хоста. Если видно —
закрывается давняя задача «журнал незагрузившихся доменов» без MITM.

**Шаг 4. `ssid`-группа** вместо пары `-W`/`-C`. Главный выигрыш: конфиг
схлопывается вдвое, уходит `routehub-netwatch.js` и дублирование узлов в
`/nodes`. Здесь уже нужен `src/stash.js`, собирающий YAML.

**Шаг 5. `consistent-hashing`** для AI — per-site sticky штатными средствами,
без страновых тиеров и без скриптов.

## Чего в Stash нет

- **smart-группы.** Замена — `consistent-hashing` плюс наш композитный балл,
  который в отличие от Surge учитывает ещё и скорость.
- **Нативного спидтеста.** Переносим свой скрипт.
- **Включения MITM из API.**
- Ручной запуск скрипта — только плитка (`$script.type = tile`), `$argument`
  в плитке нет.

## Что известно про контроллер (ЭТАП_K_STASH.md, замер 12.08)

`http://127.0.0.1:9090`, порт ядра 7890. Без ключа — 401 везде.
Живые пути: `GET /`, `/proxies`, `/proxies/{имя}`, **`PUT /proxies/{имя}` → 204**,
`/proxies/{имя}/delay`, `GET /configs`, **`PATCH /configs` → 204**, `/rules`,
`/connections` (~19 КБ), `/providers/proxies`, `ws://…/traffic?token=`.
404: `/version`, `/status`, `/api*`, `/v1*`, `/policies`, `/groups`, `/scripts`,
`/tiles`, `/ui`, `/dns/query`.

## Почему база всё-таки отдельная

Реестр устройств хранит `nonce`. Общая база перепривязала бы боевые ключи k1/k2
(вывод 12). Экономии на общей базе нет: квоты D1 считаются на аккаунт, а не на
базу (5 млн чтений строк в сутки, 100 000 записей, 5 ГБ суммарно). Значит
объединение баз давало бы только риск — отклонено в ADR-01.

## Открытое по стенду

1. `SCRIPT`-правила Stash (`SCRIPT,<имя>,POLICY`) — могут заменить половину
   логики групп, не проверялись.
2. Доступность контроллера с другого устройства — это выясняет шаг 1.
3. Замер задержки ядром (`/proxies/{имя}/delay`) — сравнить с нашим спидтестом:
   если совпадает, часть замеров можно отдать клиенту.
4. Нужен ли стенду свой конфиг-скрипт вообще, если zashboard закроет панель.
